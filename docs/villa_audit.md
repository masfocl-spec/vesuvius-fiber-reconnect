## 1. Fiber-модель: fiber_trace_3d (то, что породило предсказание 20260915 на Paris4)

**Файлы:** `vesuvius/src/vesuvius/neural_tracing/fiber_trace_3d/{model,prediction,direction,train,infer,trace2cp_tool}.py`

### 1.1 Архитектура (`model.py`)
- 3D U-Net (`Vesuvius3dUnetModel`), стадии (16, 32, 64, 128), страйды 1+2x3.
- Выход: `direction_branch_count × 7` каналов: **6 = кодировка направления «Lasagna 3x2» + 1 = presence** (`FiberTrace3DModelConfig.output_channels = 7`).
- Опция `conditioned_decoder` — декодер, обусловленный направлением (запрос одного 7-канального ответа).
- Декод направления: `decode_lasagna_direction_3x2_analytic` → единичный вектор оси (`prediction.py`); наличие клампится в [0,1]; валидность = конечность всех каналов.

### 1.2 Обучение (`train.py`, ~180 КБ)
- Целевые данные — VC3D fiber JSON (версии 1 и 3; v3 — control points с метаданными сегментов `native_fiber_trace3d`, `tracer_version: 2` — т.е. **GT-аннотации сами произведены этим же трассировщиком, полуавтоматически**).
- Лосс (`compute_losses`, стр. 1015): **косинусная близость декодированных осей** (`|dot|`, кламп 0..1) × presence на разреженных целевых вокселях + presence-лосс; выбор «ветки» направления по argmax соответствия (`eval_voxel`) или по минимальной доле на чанке.
- Спека MVP (`fiber_trace/SPEC.md`): контрастивные эмбеддинги + double-cone негативы вдоль нормали листа, джиттер направления ≤30°, пул случайных негативов 1000 — контрастная часть заявлена, в v3-тренировке основное — направление+presence.

### 1.3 Инференс (`infer.py`)
- Тайловое предсказание поля (tile 512, overlap 96, border 32 по умолчанию из `las_manager`), мульти-GPU, чанки 64³, blosc-zstd, пирамида уровней — пишется zarr-продукт + `.lasagna.json`-манифест + `inference.json` (provenance с git-коммитом). Это ровно тот пайплайн, что произвёл `20260411134726-fibers-20260915212757-L1` (наш data_plan).
- Управляемый запуск: `las_manager` (tmux, prefetch, snapshots) — **как официально гонят инференс на новые свитки** (в README перечислены и новые: `PHerc0332` в примерах `volume ls`).

### 1.4 Трассировка: trace2cp_tool.py (~378 КБ, «Trace2CP»)
- Полуавтоматический трассировщик VC3D: пользователь ставит control points, модель ведёт волокно между ними.
- Механика: **beam search** (`_NativeBeamNode`, `beam_width=8`, lookahead) по предсказанному полю (направление+presence); трассировка в две стороны; шаг/гладкость настраиваются (`NativeTrace2CpConfig`).
- Есть режимы whole-fiber (одноклик → целое волокно, `NativeWholeFiberResult`) и multi-fiber.
- **Сшивка концов (ключевая находка аудита):** `fuse_forward_reverse_traces` (стр. ~5269) — прямая и обратная трассы сшиваются выбором пары точек с минимумом `score = 2.0·gap + combined_lengths` (с тай-брейками по длинам), затем обе части варпятся к середине. **Эвристика чисто дистанционная — ни тангенсов, ни кривизны.**
- Важно: это ЛОКАЛЬНАЯ сшивка внутри одного сегмента между двумя control points пользователя — НЕ глобальное пере-соединение независимых фрагментов.

### 1.5 fiber_trace_2d
- 2D-вариант трассировки полосами (strips) на развернутой поверхности; `strip_geometry.control_point_line_index` — геометрия сегментов между CP.

## 2. Mutex Watershed affinity-стек (второй важный пропуск прошлого аудита)

**Файлы:** `vesuvius/src/vesuvius/models/datasets/mutex_affinity_dataset.py`, `training/trainers/mutex_affinity_trainer.py`, `evaluation/affinity_metrics.py`, `image_proc/run/generate_mutex_graph.py`, `segmentation/vc_proofreader/`

- Полноценная реализация **Mutex Watershed аффинитетов** (техника разделения слипшихся/пересекающихся структур из нейросегментации: обучение предсказывать притягивающие/отталкивающие рёбра; лоссы — Dice по секции 5.1 статьи Mutex Watershed).
- `generate_mutex_graph.py` строит attractive/repulsive графы из объёмов (порог foreground, long-range stride, CC-анализ).
- `vc_proofreader/extract_good_labels.py` — отбор «хороших» чанков для вычитки (фильтр по количеству связных компонент 4–50 и проценту метки) — инфраструктура подготовки аффинитетных данных.
- Статус: зарегистрирован как trainer `mutex_affinity` в общем CLI моделей (`training/cli.py:378`). **К волокнам в текущем коде НЕ привязан** — это общий потенциал стека, который можно применить к fiber-связности (в т.ч. к нашим перекрёсткам).

## 3. Волокна в спиральной подгонке (spiral-fitting)

### 3.1 H/V-классификация: `spiral_helpers.classify_fiber_hv` (стр. 286)
Приоритет: ручной тег VC3D → автотег (при certainty ≥ порога) → **геометрический фолбэк по всей полилинии: вертикальное, если z-протяжённость ≥ min_z_fraction длины пути; горизонтальное, если ≤ 1−min_z_fraction; иначе без тега**. (Ось z — длинная ось свитка.) Теги ведут радиальные смещения и связывание сторон патча.
→ Это ОФИЦИАЛЬНАЯ реализация «сигнала 1» из нашего плана (классификация семейства H/V), но на уровне целого волокна, а не висячего конца.

### 3.2 Same-sheet links: `bracket_fiber_links.py`
- Геометрический вывод топологии листа из волокон: горизонтальное волокно, намотанное >1 витка, создаёт радиальный зазор = один winding; **вертикальное волокно, «зажатое» между соседними витками, по построению лежит на обратной стороне того же листа** — линкуется с горизонтальным на ближайшем пересечении (биннинг по unwrapped θ, допуск по z, критерии min/max радиального зазора).
- Линки пишутся в VC3D-формат (branches, с продвижением line points в control points, перенумерацией, pending-статусом, бэкапами; dry-run по умолчанию).
- Есть защита `drop_links_inside_gap_spans` — линк не ставится внутри «пролётов» волокна.
→ Это ОФИЦИАЛЬНАЯ автоматизация winding-аннотаций — тот путь ценности, который мы описывали; инструмент уже существует и опирается на ЦЕЛОСТНЫЕ волокна (обрывы волокон напрямую режут его возможности — наша работа восполняет ровно это).

### 3.3 Супервизия подгонки волокнами
- `fit_spiral.py`: импортирует fiber point collections, `classify_fiber_hv`, `resolve_fiber_links`, `get_fiber_direction_loss` — волокна участвуют в потерях подгонки (направление) и в радиальных смещениях (H/V-специфичных).
- `fiber_direction_samples.py`: разреженные confidence-weighted сэмплы направления из fiber-предсказаний (в каждой ячейке удерживается воксель с максимальным presence) — канал супервизии без полной выкачки объёма.
- Конфиги свипов содержат варианты `no_fibers` / `no_fiber_links` / `no_tracks` — систематические абляции вклада волокон.

## 4. Датасетные генераторы: foundation/datasets/fibers-dataset

| Скрипт | Метод (по коду) |
|---|---|
| `fibers-dataset-generator.py` | NML (WebKnossos) → воксельные метки: **адаптивная интерполяция узлов по кривизне** (рекурсивная subdivision при пороге 0.1), растеризация трубок, distance transform; вход — аннотации типа `fibers_s5_..._v03.nml` (пример Elian Rafael Dal Prá) |
| `hz-vt-generator.py` | **PCA на воксельном облаке** каждого дерева → классификация H/V (z_threshold 1/√2), метки пересечений (класс «intersection» по близости H и V трубок) |
| `voxels-to-skeleton.py` | Обратная операция: объём → **Kimimaro skeletonization** → ветви скелета → NML для WebKnossos (создание заготовок аннотаций из предсказаний) |
| `detect-missed-fibers.py` | Поиск волокон, пропущенных аннотатором (сравнение меток с предсказанием, Cupy-ускорение) |
| `register-meshes-to-fibers/` (рядом) | регистрация мешей сегментов к волокнам |

→ Подтверждает: ручные аннотации fiber-skeletons (2025-07) — деревья БЕЗ ветвлений (~99% по сторонней статистике), т.е. люди сами резали волокна на перекрёстках; датасетная механика это кодифицирует.

## 6. VC3D (volume-cartographer) — источник нашего GT

- Интерактивное приложение (С++/Python); fiber pane с line-annotation widget; MCP-инструменты (`tools/vc3d-mcp`); agent bridge.
- Формат `vc3d_fiber` v3: `line_points` + `control_points` с per-сегментными метаданными оптимизатора — именно из него наш `eval_gt.py` берёт GT (65 eval_fibers Paris4).
- Наша метка `optimization_mode: "native_fiber_trace3d"` в GT-файлах означает: **GT-волокна получены полуавтоматическим трассировщиком п.1.4 и выверены людьми** (VC3D workflow pending/approved).

## 7. Выводы аудита для нашего проекта

### 7.1 Велосипедометр (окончательный, по коду)
| Искали | Найдено? |
|---|---|
| Глобальное пере-соединение фрагментов волокон (Hungarian/какое-либо) | **НЕТ** — единственная сшивка концов `fuse_forward_reverse_traces` локальна (внутри сегмента CP↔CP), дистанционная |
| Тангенс/кривизна в стоимостях сшивки | **НЕТ** — в официальной эвристике только gap+длины |
| Разрешение перекрёстков волокон | **НЕТ** — ни в трассировщике, ни в spiral-fitting; mutex-стек существует, но к волокнам не подключён |
| H/V-классификация | **ДА**, целого волокна (`classify_fiber_hv`, z-extent fallback + VC3D-теги); на уровне висячего конца — нет |
| Интенсивность/каналы через разрыв | **НЕТ** |
| Регулярность плетения как приор | Частично: геометрия витков в `bracket_fiber_links` (это сильнее — топология из намотки) |

### 7.2 Как это меняет наш план
1. **Наш A1-результат получил официальное подкрепление:** единственная в официальном коде эвристика сшивки — дистанционная. Наша систематика (дистанция ≥ геометрии на реальном шуме) согласована с выбором разработчиков villa, но нами ещё и измерена — этого ни у кого нет.
2. **«Сигнал 1» (H/V по отступу от конца)** — официальная классификация существует для целых полилиний; наша новизна — классификация ВИСЯЧЕГО КОНЦА вдали от целой полилинии. Стоит переиспользовать их z-extent-идею локально (окно вдоль цепи).
3. **Mutex affinity-стек** — готовая инфраструктура, к которой можно прикрутить fiber-аффинитеты (обучаемая альтернатива нашим ручным стоимостям; закрывает «сигнал 4» из нашего плана).
4. **Путь ценности подтверждён кодом:** `bracket_fiber_links` + fiber-supervision в fit_spiral потребляют ЦЕЛОСТНЫЕ волокна; разрывы режут θ-биннинг и бракет-геометрию. Наш реконнект — недостающий этаж под существующим официальным инструментом.
5. **GT-честность:** eval_fibers — полуавтоматические аннотации (native_fiber_trace3d), что усиливает нашу оговорку о хрупкости GT-привязки: ошибки трассировщика системно коррелируют с ошибками детектора.

### 7.3 Что осталось непокрытым этим аудитом
- Внутренности VC3D-приложения (volume-cartographer, С++) — только структура и формат; GUI-виджет трассировки не читался построчно.
- `deprecated/thaumato-anakalyptor` (сшивка листов, Mask3D, graph solver) — на уровне каталога: это про ЛИСТЫ, не волокна.
- Снапшоты/чекпойнты моделей и конфиги конкретных прогонов — вне репо (внешние snapshot-директории las_manager).
- Discord и приватные прогоны — недоступны принципиально.
- `dinovol`, `ink-detection` — вне fiber-фокуса, не читались.
